Légende

PKidentifiant unique de la ligne. FKnuméro d'une ligne d'une autre table. (1,1)un et un seul. (0,1)zéro ou un. (0,n)zéro, un ou plusieurs. lectureun compte écrit zéro, un ou plusieurs retours ; chaque retour est écrit par un et un seul compte ; un retour a zéro ou une capture d'écran, rangée comme les autres fichiers dans FICHIER. orangetable nouvelle.

Les rubriques

RETOUR nouvelle

  • sorte : probleme ou idee, le choix de l'utilisateur (gardé tel quel)
  • texte : son message, de 10 à 2 000 caractères
  • page : la page où il était, ex. /demandes/nouvelle
  • appareil : telephone ou ordinateur
  • navigateur : ex. « Chrome sur Android »
  • statut : a_traiter (la routine le lira) ou injurieux (gros mots : gardé pour l'administrateur, jamais lu par la routine)
  • cree_le : le moment de l'envoi

fichier_id est vide sans capture. Quand la capture est effacée (problème réglé, idée refusée), la ligne de FICHIER est supprimée et fichier_id redevient vide tout seul.

La limite de 5 messages par jour n'est rangée nulle part : rafals compte les lignes du compte depuis minuit (heure de Paris) au moment de l'envoi.

Plus tard : les lots 13.2 et 13.3 ajouteront dans un autre fichier SQL ce dont la routine a besoin (sorte corrigée, groupe des doublons, branche git, corrigé / accepté / refusé…), avec leur propre MLD à valider.

COMPTE · FICHIER

Ne changent pas. La capture d'écran est un fichier comme les autres (accords des parents, photos) : FICHIER garde où il est rangé dans le placard à fichiers (Garage).

Ce que fera rafals avec cette table (lot 13.1)

  1. « Un problème ? Une idée ? » dans le menu du compte (onglet « Moi » sur téléphone), seulement connecté.
  2. La fenêtre : [Un problème] [Une idée], le texte, [+ Ajouter une capture d'écran] ; page, appareil et navigateur ajoutés tout seuls.
  3. Refus au 6ᵉ message du jour, et pour un texte de moins de 10 caractères.
  4. Gros mots : même filtre que les avis → statut = injurieux.
  5. Message « Merci, c'est envoyé. Nous regardons chaque soir. »

Exemples de vraies lignes

RETOUR n° 1 : auteur = Julie, sorte = probleme, texte = « Le bouton Publier ne répond pas sur mon téléphone », page = /demandes/nouvelle, appareil = telephone, navigateur = « Chrome sur Android », fichier = n° 87, statut = a_traiter, 09/11/2026 20:14.

Traduction : ce soir, Julie a voulu publier une demande depuis son téléphone et le bouton n'a rien fait. Elle a joint une photo de son écran (fichier n° 87). La routine de la nuit lira ce message et cherchera le problème sur la page « Publier une demande ».

RETOUR n° 2 : auteur = Karim, sorte = idee, texte = « Ce serait bien de pouvoir mettre une vidéo de mon travail », page = /profil, appareil = ordinateur, navigateur = « Firefox sur Windows », fichier = vide, statut = a_traiter, 09/11/2026 21:02.

Traduction : Karim, électricien, propose une idée depuis son profil, sans capture. La routine préparera l'ajout à part ; il n'entrera dans le site que si Raphael clique [Accepter].

RETOUR n° 3 : auteur = Paul, sorte = probleme, texte = « (insultes) », page = /messages, appareil = ordinateur, navigateur = « Edge sur Windows », fichier = vide, statut = injurieux, 09/11/2026 22:40.

Traduction : le message de Paul contient des insultes : la routine ne le lit jamais ; il reste visible pour l'administrateur, qui peut décider de bloquer le compte.
